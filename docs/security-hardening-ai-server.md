# AI Server Network Hardening

**Date:** 2026-07-26  
**Scope:** AWS network layer for `tablescope-ai-server` (GPU/LLM host) and the `tablescope` app server.  
**Goal:** Ensure the AI server is not reachable from the public internet, does not communicate directly with the public internet, and that all customer data vectorization stays inside the Tablescope VPC environment.

## 2. What changed

### 2.1 Cross-region private connectivity

- Created and accepted inter-region VPC peering `pcx-002fbf432312ba467` between the app VPC (`172.31.0.0/16`) and the AI VPC (`10.200.0.0/16`).
- Added routes:
  - App VPC route table `rtb-0b4fefb8804f77f32` → `10.200.0.0/16` via `pcx-002fbf432312ba467`.
  - AI VPC public route table `rtb-097f7cabbeae7badc` → `172.31.0.0/16` via `pcx-002fbf432312ba467`.
  - AI VPC private route table `rtb-09326bc1bca0a3cc9` → `172.31.0.0/16` via `pcx-002fbf432312ba467`.

### 2.2 Service URLs switched to private addresses

- `/home/ubuntu/tablescope/.env` on the app server:
  ```
  TABLESCOPE_AI_API_URL=http://10.200.2.26:8000
  ```
- `/home/ubuntu/tablescope/ai-server/.env` on the AI server:
  ```
  TABLESCOPE_APP_URL=http://172.31.15.57:8000
  ```

These replace the previous public-IP references (`32.186.54.52` and `13.57.117.13`), so public IP changes no longer break app↔AI reachability.

### 2.3 AI server security group

- **Inbound:**
  - TCP `8000` from `172.31.0.0/16` (app VPC).
  - TCP `22` from `172.31.0.0/16` (app VPC) only.
- **Outbound:**
  - TCP `8000` to `172.31.0.0/16` (app VPC).
  - All traffic to `10.200.0.0/16` (AI VPC internal).
- Removed `0.0.0.0/0` SSH inbound and all `0.0.0.0/0` outbound internet access.

### 2.4 App server security group

- TCP `80` from `0.0.0.0/0` — ACME HTTP-01 challenge and HTTPS redirect only.
- TCP `443` from `0.0.0.0/0` — application traffic through nginx.
- TCP `8000` from `10.200.0.0/16` — AI server→platform-api private API.
- TCP `22` from `172.31.0.0/16` only — no public SSH.
- Removed `0.0.0.0/0` SSH.

### 2.5 Local binding of internal services on the app host

In `/home/ubuntu/tablescope/docker-compose.yml`:

- `teiid` ports changed to `127.0.0.1:8095:8080`, `127.0.0.1:35442:35432`, `127.0.0.1:9990:9990`.
- `pgbouncer` port changed to `127.0.0.1:35443:5432`.

These services are now reachable only from the host itself; they are no longer exposed on the host's public/private interfaces.

## 6. Remaining hygiene

- The AI server still has an auto-assigned public IP and an Internet Gateway route. The security group now blocks all inbound/outbound internet traffic, so the public IP is effectively unused. For full hygiene, migrate the instance to the existing private subnet `subnet-06813a6c90b9c9d12` and manage it via SSM or a VPC bastion.
- Private IP addresses are stable for the lifetime of an instance. If either instance is rebuilt, update the `.env` URLs or move to Elastic Network Interfaces / Route 53 private hosted-zone records.

---

## 7. How to roll back

1. Revert `.env` files to the previous public URLs.
2. Delete the peering route entries and the VPC peering connection `pcx-002fbf432312ba467`.
3. Restore original security-group rules.
4. Revert `docker-compose.yml` port bindings to `0.0.0.0:<port>:<port>`.
5. Run `docker compose up -d` on both hosts.
